# Probar la exploración de vacantes del estudiante

Esta entrega cubre el backend de HU-04: listado filtrado y paginado y detalle de vacantes disponibles para el estudiante. El formulario, el esquema Zod y su integración corresponden a la fase de frontend.

## Preparación

Con Docker Desktop y PostgreSQL local funcionando, inicia o reinicia la API para cargar la rama:

```powershell
cd C:\Proyectos\UPractice\backend
dotnet run --project .\src\UPractice.Api --launch-profile http
```

Abre `http://localhost:5294/swagger`. Ejecuta `POST /api/v1/auth/login` con el estudiante demo `ana.lopez@unah.hn` y tu contraseña demo local; pega solo `accessToken` en Authorize. El estudiante debe estar activo y sus claims deben corresponder a su universidad actual. Los estudiantes utilizan su propia contraseña de registro.

Para tener una vacante nueva disponible, un reclutador puede crearla siguiendo [HU-E03](HU-E03.md), con estado Publicada, fecha vigente y habilitación Aprobada de su empresa en la universidad del estudiante.

## Listado y filtros

Ejecuta `GET /api/v1/vacantes`. La respuesta 200 contiene `items`, `pagina`, `tamanoPagina`, `totalRegistros` y `totalPaginas`.

| Parámetro opcional | Comportamiento |
|---|---|
| `busqueda` | Busca texto en título o nombre comercial de la empresa, sin distinguir mayúsculas. Se recortan espacios exteriores; blanco equivale a omitirlo. Los caracteres `%` y `_` son texto literal. |
| `carreraId` | Busca vacantes que acepten ese ID de carrera. Puedes obtenerlo del detalle de una vacante en `carrerasDetalle[].id`. |
| `modalidad` | Presencial, Remota o Hibrida. |
| `remunerada` | `true` o `false`; omitirlo permite ambas. |
| `pagina` | Desde 1; predeterminado 1. |
| `tamanoPagina` | Entre 1 y 50; predeterminado 10. |

Los filtros se combinan. Por ejemplo: `/api/v1/vacantes?busqueda=desarrollo&modalidad=Remota&remunerada=true&pagina=1&tamanoPagina=10`.

Los resultados se ordenan por fecha de publicación descendente y, para empates, ID descendente. El total se cuenta después de filtrar y antes de paginar. Una página fuera de los resultados devuelve elementos vacíos y conserva los totales.

No se aplica automáticamente la carrera del estudiante como filtro: se pueden explorar otras carreras y comprobar el indicador de requisitos. Un ID de carrera inexistente bien formado devuelve cero coincidencias; un UUID vacío o mal formado devuelve 400.

## Visibilidad y detalle

Copia un `items[].id` y consulta `GET /api/v1/vacantes/{id}`. El detalle agrega descripción, cupos, carreras con facultad/universidad, índice mínimo y habilidades con su indicador `esRequerida`.

Ambos GET muestran exclusivamente vacantes:

- Publicadas.
- Con fecha de cierre igual o posterior a hoy en Honduras (`America/Tegucigalpa`). El propio día de cierre sigue vigente.
- De empresas activas y con habilitación Aprobada en la universidad del estudiante autenticado.

El detalle de una vacante fuera de ese catálogo devuelve 404, igual que un ID inexistente. Estas condiciones también se comprueban si el estudiante se había postulado antes. El historial de postulaciones tiene sus propias reglas de lectura y no se modifica en esta entrega.

## Indicadores personalizados

`cumploRequisitos` es informativo y se calcula con los datos actuales del estudiante. Es verdadero únicamente si:

1. Existe su perfil y su carrera está permitida por la vacante.
2. Su índice alcanza el mínimo solicitado, cuando se define uno.
3. Tiene todas las habilidades marcadas como requeridas; las deseables no afectan el resultado.

Esta fórmula se estableció para HU-04 el 22 de noviembre de 2026. Un perfil pendiente o rechazado permite explorar y calcular el indicador con sus datos; no tener perfil produce `false`. Las habilidades de otros estudiantes no se utilizan.

Ejemplo: para Sistemas, índice mínimo 80, C# requerida y Docker deseable, un estudiante de Sistemas con índice 85 y C# obtiene `true` aunque no tenga Docker. Si le falta C# o su índice es 75, obtiene `false`.

`yaPostulado` es verdadero si existe cualquier postulación propia a esa vacante, incluida una Retirada. Una postulación de otro estudiante no cambia el indicador. Esto permite usar la reactivación de la fila existente desde el panel en lugar de crear otra postulación.

Estos indicadores no conceden permiso para postularse. HU-05 conserva sus guardias de verificación de perfil, carrera, CV y práctica aceptada. Conforme a D-06, el índice mínimo es deseable y no bloquea la postulación; el flujo actual tampoco usa habilidades como bloqueo. El `CumpleRequisitos` persistido en una postulación sigue siendo la fotografía del índice calculada por HU-05, distinta del indicador informativo de esta consulta.

## Errores y permisos

| Caso | Respuesta esperada |
|---|---|
| Sin token o identidad que ya no es válida | 401 |
| Reclutador, AdminEmpresa, Coordinador o SuperAdmin | 403 |
| Página cero/negativa o tamaño fuera de 1–50 | 400 en el campo correspondiente |
| UUID, modalidad, booleano o entero mal formado | 400 compartido de ModelState/validación |
| Vacante inexistente o fuera del catálogo permitido | 404 |

Se conserva el contrato IAM existente: `GeneradorJwt` no emite `pwd_temp` para Estudiante, cuyo registro es propio. La restricción D-17 de cuentas creadas por otra persona sigue aplicándose a sus roles y no se modifica en HU-04.
